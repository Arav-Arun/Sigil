How it works

From a photo to a proof

Four steps. Searching only decides where to look, the face comparison decides who it is, and the result is sealed so anyone can check later that it was not changed.

  1. 1

    Read the face

    Your photo is scanned for faces, and each one is turned into a list of numbers that describes it. Those numbers are biometric data, so they stay in memory: never saved to disk, never written into the record, never put on a blockchain.

  2. 2

    Search the open web

    Four independent sources are searched at once, so one of them failing or coming back empty does not end the search. This step only suggests pages worth checking. It never decides who anyone is.

    Google LensVisual matches and pages
    ExaRelated public pages
    WikidataCurated public portraits
    Page crawlerOther photos on a page
  3. 3

    Compare every result

    Each result's image is downloaded and every face in it is compared with yours. A face too small to judge is reported as not sure rather than forced into an answer. A result that came first in the search is still rejected if the face does not match.

    MatchNot sureNo match
    When the evidence is genuinely borderline, the answer is “not sure”. Naming the wrong person is worse than admitting uncertainty.
  4. 4

    Record the proof

    Every detail of the verified result is combined into one short fingerprint and written to the Ethereum Sepolia blockchain. Only that fingerprint and a timestamp go on chain: no photo, no name, no face data. Checking it later needs no wallet and no account, and if anything was altered the check names the exact detail that changed.

Nothing personal is stored

The contract holds a hash, an address, a timestamp and a format version. Biometric data on an immutable public ledger is a permanent harm, so none is written.

Checking needs no wallet

Re-verification is a read-only blockchain lookup. A proof that required the claimant's private key would not be a proof.

A change is named, not just noticed

A single hash would only tell you something changed. The inclusion proof identifies the exact detail, for example, the post address.
